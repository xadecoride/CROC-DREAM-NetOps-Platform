# Задачи по спринтам (Jira)

Раскладка работ по трём спринтам хакатона. Формат: спринт → участник → описание задачи → дедлайн.
Задачи сознательно связаны между собой: то, что делает один, становится входом для другого.

Разработка идёт до 16 октября — к 18:00 этого дня проект должен быть готов. Спорные вопросы и то, что не успеем закрыть к этому сроку, выносим на онлайн-отборочный этап (19–21 октября) — там же принимаем финальные решения.

---

## Спринт 1 (28 сентября — 4 октября)

**Фокус спринта:** поднять виртуальную лабу, согласовать формат YAML-файлов и сделать работающий каркас API.

### МП (я)

1. **Расписать ТЗ на команду и завести задачи в Linear**
   Описание: разбить общий текст ТЗ на конкретные задачи по каждому человеку, назначить исполнителей и дедлайны, чтобы у всех была понятная картина. Сразу зафиксировать правило - у каждого в работе максимум одна задача.
   Дедлайн: 30 сентября

2. **Описать структуру YAML-файлов с сетевыми параметрами**
   Описание: написать, из каких блоков состоят YAML-файлы (интерфейсы, BGP, ACL), какие поля обязательные. Согласовать этот формат с Аней (она должна по нему описать сеть), Тимофеем (он делает инвентарь вместо NetBox) и Лёшей (он по нему будет писать валидацию в Pydantic). После согласования закинуть схему в репозиторий, чтобы все работали от одного документа.
   Дедлайн: 1 октября

3. **Подготовить репозиторий и доску задач**
   Описание: создать репо на GitHub, настроить структуру папок, подключить линтеры (Ruff, Black), завести колонки на доске (Бэклог → Готово к работе → В работе → Проверка → Готово). Проверить, что у всех есть доступ.
   Дедлайн: 30 сентября

4. **Держать синки и следить за ходом спринта**
   Описание: созвон на 15 минут — что сделал, что беру, какие блокеры. Длинные технические споры переносить на отдельный созвон. Следить, чтобы никто не подхватил вторую задачу, пока не сдал первую.
   Дедлайн: весь спринт

### Аня

1. **Рассчитать адресацию на лабораторную фабрику**
   Описание: посчитать подсети /31 на межузловые линки, /32 на Loopback, распределить номера ASN под eBGP. На выходе — таблица адресации, по которой будут собираться и лаба, и YAML-файлы.
   Дедлайн: 30 сентября

2. **Нарисовать L3-схему на 4 узла**
   Описание: двухуровневая CLOS-топология — 2 Spine на Arista EOS и 2 Leaf на Cisco IOS-XE. Схему сразу отдать Тимофею, он по ней будет писать манифест Containerlab. Параллельно схему показать МП, чтобы он зафиксировал её как основную.
   Дедлайн: 1 октября

3. **Собрать эталонные конфиги под два вендора**
   Описание: руками собрать рабочие конфиги для Cisco и Arista — порты, BGP, базовые ACL. Это наши эталоны, по ним потом будут писаться шаблоны и по ним будет считаться дифф. Конфиги положить в репозиторий и передать Тимофею, чтобы он прогнал их на стенде.
   Дедлайн: 3 октября

4. **Описать правила проверки здоровья сети (первый вариант)**
   Описание: выписать команды диагностики (show ip bgp summary, show ip interface brief, ping), что считать нормой и при каких значениях деплой считается аварийным. Этот список уйдет Максиму и Лёше — у них из этого будут post-check тесты.
   Дедлайн: 4 октября

### Тимофей

1. **Написать манифест clab.yml и поднять стенд**
   Описание: взять схему от Ани и поднять в Containerlab 4 устройства — 2x Arista cEOS и 2x Cisco IOS-XE. Проверить, что все ноды стартуют и между ними есть связность.
   Дедлайн: 2 октября

2. **Настроить сетевой доступ к стенду**
   Описание: изолированная виртуальная сеть управления, проброс SSH-портов так, чтобы бэкенд и скрипты Максима достучались до каждой ноды по локальному адресу. Доступы и логины сразу отдать Лёше и Максиму — иначе у них всё встанет.
   Дедлайн: 3 октября

3. **Скрипт быстрого сброса стенда (Reset Lab)**
   Описание: bash-скрипт, который за ~10 секунд возвращает коммутаторы к исходному состоянию после аварийных тестов. Понадобится, когда начнем ломать сеть для проверки откатов.
   Дедлайн: 4 октября

4. **Начать инвентарь в YAML вместо NetBox**
   Описание: по структуре, которую согласовал МП, завести YAML-файл с устройствами стенда (hostname, management_ip, платформа, роль, логины). Это наш Source of Truth вместо NetBox, дальше по нему будет работать бэкенд Лёши.
   Дедлайн: 4 октября

### Лёша

1. **Развернуть каркас проекта на FastAPI**
   Описание: базовая структура приложения, роутеры, health-check эндпоинт, чтобы сервис поднимался и отвечал. Завести venv/poetry, подключить линтеры.
   Дедлайн: 1 октября

2. **Спроектировать таблицы в PostgreSQL**
   Описание: таблицы под устройства, задачи (jobs), снимки конфигураций и историю дрейфа. Настроить миграции через Alembic. Перед началом свериться с МП по формату YAML — модель данных в базе должна повторять то, что описано в инвентаре.
   Дедлайн: 2 октября

3. **Сделать CRUD по устройствам**
   Описание: эндпоинты GET /api/v1/devices и GET /api/v1/devices/{id}, валидация через Pydantic (корректность IP, диапазон ASN, уникальность router-id). Это то, к чему сразу подключится фронт Максима.
   Дедлайн: 3 октября

4. **Поднять postgres в docker-compose и проверить миграции**
   Описание: база должна подниматься одной командой вместе с бэкендом, миграции применяются автоматически. На выходе — рабочее окружение, куда устройства заводятся через API.
   Дедлайн: 4 октября

### Максим

1. **Написать проверочные скрипты подключения к стенду на Nornir + Scrapli**
   Описание: скрипты, которые подключаются по SSH ко всем 4 нодам, собирают running-config и выполняют произвольную команду. Берем доступы у Тимофея (после 3 октября — можно раньше, начиная с одной ноды). Эти скрипты — основа для всего дальнейшего пайплайна, их же отдаешь Лёше для воркеров.
   Дедлайн: 3 октября

2. **Поднять каркас фронтенда на Vite + React**
   Описание: первая страница — список устройств с индикаторами статуса (IN_SYNC / DRIFT_DETECTED / UNREACHABLE). Пока данные можно получить моком, но формат ответа согласовать с Лёшей, чтобы потом просто переключиться на реальный API.
   Дедлайн: 3 октября

3. **Подключить фронт к API бэкенда**
   Описание: вытянуть список устройств с GET /api/v1/devices и отрендерить на странице. Договориться с Лёшей по формату JSON, чтобы фронт не переделывать дважды.
   Дедлайн: 4 октября

**Контрольная точка 1 (4 октября):** 4 коммутатора работают в Containerlab и отвечают по SSH. Бэкенд сохраняет устройства в базу. Формат YAML согласован, фронт показывает список устройств.

## Спринт 2 (5 октября — 11 октября)

**Фокус спринта:** генерация конфигов из YAML по шаблонам, расчет команд наката и отката, очереди задач.

### МП (я)

1. **Проверить сквозную передачу данных: YAML → бэкенд → шаблоны**
   Описание: лично прогнать цепочку — поменял параметр в YAML, бэкенд его увидел, шаблон сгенерировал команды. Там, где данные теряются между людьми, разруливать на месте.
   Дедлайн: 9 октября

2. **Следить за доской и блокерами**
   Описание: ежедневные синки, контроль WIP-лимитов, не давать команде распыляться.

   Дедлайн: ежедневно весь спринт

3. **Начать готовить сценарий демонстрации**
   Описание: схематично описать, что показываем на защите: заводим устройство, вносим изменение в YAML, смотрим дифф, применяем, ломаем — видим откат. По этому сценарию потом пойдет репетиция.
   Дедлайн: 11 октября

### Аня

1. **Составить список служебных строк CLI для фильтрации**
   Описание: выписать все, что ОС плюет в конфиг автоматически — Building configuration..., счетчики байт, временные метки, сертификаты, ключи. Это нужно, чтобы diff не ругался на мусор. Список отдать Тимофею (он встраивает в нормализацию) и Максиму (он делает расчет диффа).
   Дедлайн: 6 октября

2. **Дописать ACL в эталонные конфиги и проверить их на стенде**
   Описание: добавить к эталонам правила фильтрации трафика, убедиться, что конфиги применяются без ошибок и трафик при этом не рвется.
   Дедлайн: 8 октября

3. **Проверить сгенерированные конфиги по-человечески**
   Описание: когда шаблоны Тимофея начнут выдавать команды, посмотреть глазами сетевика — корректные ли команды, ничего ли не хватает. Фидбек вернуть ему же, чтобы он поправил шаблоны.
   Дедлайн: 9 октября

### Тимофей

1. **Написать шаблоны Jinja2 под Cisco и Arista**
   Описание: по эталонам Ани сделать шаблоны base.j2, interfaces.j2, bgp.j2 отдельно для cisco_iosxe и arista_eos. Шаблоны должны кушать наш YAML-инвентарь. Готовые шаблоны отдать Лёше — он подключит их к бэкенду.
   Дедлайн: 7 октября

2. **Отладить hier_config на живом стенде**
   Описание: снять running-config, скомпилировать intended из шаблонов, прогнать через hier_config и убедиться, что на выходе получаются осмысленные remediation и rollback. Поправить синтаксис там, где библиотека спотыкается.
   Дедлайн: 9 октября

3. **Развернуть Prometheus + Grafana**
   Описание: поднять мониторинг, настроить scrape со стенда и первые дашборды — состояние BGP-соседей, статус портов. Метрики понадобятся и для health-check, и для красивого экрана на демо.
   Дедлайн: 11 октября

### Лёша

1. **Подключить Redis и Celery**
   Описание: сетевые операции (подключение по SSH, сбор конфигов) уводить в фоновые воркеры, чтобы веб-сервер не вис. Настроить, чтобы задача ставилась в очередь и фронт могла опрашивать её статус.
   Дедлайн: 7 октября

2. **Сделать эндпоинты под задачи: dry-run, статус, дифф**
   Описание: POST /api/v1/jobs/dry-run (возвращает job_id), GET /api/v1/jobs/{id} (статус и прогресс), GET /api/v1/jobs/{id}/diff (running, intended, remediation, rollback). Внутрь воркера подключить шаблоны Тимофея и модуль иерархического сравнения Максима.
   Дедлайн: 9 октября

3. **Реализовать жизненный цикл задачи с логами**
   Описание: PENDING → RUNNING → SUCCESS / FAILED, на каждом шаге пишем подробные логи, чтобы потом отдавать их во фронт. Ошибки не терять — падение задачи должно быть видно, а не молчание.
   Дедлайн: 9 октября

4. **Свести конвейер dry-run в одну задачу Celery**
   Описание: подключение к устройству → снятие конфига → нормализация → расчет диффа → сохранение результата. К 11 октября это должно отрабатывать по кнопке из API на всех 4 нодах.
   Дедлайн: 11 октября

### Максим

1. **Автоматизировать сбор конфигов скриптом**
   Описание: python-скрипт, который одной командой обходит стенд и сохраняет running-config каждого устройства в файлы — для отладки и для передачи в бэкенд. По необходимости доработать Nornir-модуль под параллельный сбор.
   Дедлайн: 6 октября

2. **Встроить hier_config в модуль работы с сетью**
   Описание: связать то, что приходит со Scrapli, с расчетом диффа — получить remediation_config и rollback_config. Согласовать с Лёшей сигнатуру функции, чтобы он вызвал ее из воркера Celery.
   Дедлайн: 8 октября

3. **Страница запуска dry-run и просмотра статусов**
   Описание: на фронте — кнопка «Холостой прогон» по выбранным устройствам, экран с прогрессом задачи и логами по мере выполнения. Подключить к API Лёши, проверить на живом стенде.
   Дедлайн: 11 октября

**Контрольная точка 2 (11 октября):** система берет данные из YAML, генерирует CLI под два вендора, сравнивает с текущим состоянием стенда через hier_config, показывает дифф и команды отката. Задачи крутятся в Celery, статусы видны во фронте. Grafana показывает первые метрики.

## Спринт 3 (12 октября — 16 октября)

**Фокус спринта:** транзакционный деплой с откатом, проверка дрейфа, финальный интерфейс и сдача кейса. Спринт сжатый: проект должен быть готов к 16 октября, 18:00, поэтому хвостов не оставляем — все задачи закрываем не позднее 15 октября, 16-го только финальная сборка и отправка.

Спорные вопросы, по которым команда не придет к единому мнению внутри спринта, разбираем на онлайн-отборочном этапе 19–21 октября — на нём же закрываем все хвосты.

### МП (я)

1. **Провести сквозное тестирование всего пайплайна**
   Описание: пройти всю цепочку от изменения в YAML до применения на стенде и отката. Составить список найденных проблем и раскидать их по исполнителям с дедлайнами. Ничего не закрывать, пока блокеры не сняты.
   Дедлайн: 14 октября

2. **Собрать документацию и презентацию к сдаче**
   Описание: пояснительная записка, слайды, видеоролик с демонстрацией. Отработать сценарий выступления на 7 минут так, чтобы он не зависел от того, что пойдет не так в живом демо.
   Дедлайн: 15 октября

3. **Контроль финального дедлайна**
   Описание: 16 октября 18:00 — жесткий срок, к нему проект должен быть готов. Проверить, что репозиторий оформлен, docker-compose поднимает всё одной командой, ролик и записка загружены в форму организаторов. Не допустить, чтобы что-то из этого осталось на последний час.
   Дедлайн: 16 октября, 18:00

### Аня

1. **Финализировать правила Health-Check**
   Описание: утвердить команды и пороги: BGP в Established с принятыми префиксами, порты up/up, ping без потерь (потери >20% — авария). Отдать Лёше и Максиму — из этого они соберут pre-check и post-check тесты.
   Дедлайн: 13 октября

2. **Устроить на стенде аварийные сценарии и проверить откат**
   Описание: намеренно сломать сеть — уронить BGP-соседа, закрыть линк — и убедиться, что платформа ловит сбой, блокирует коммит и возвращает конфиг назад. Список сценариев отдать МП, он включит их в сквозное тестирование.
   Дедлайн: 14 октября

3. **Проверить финальные конфиги перед демо**
   Описание: убедиться, что эталоны в репозитории актуальны, ACL на месте, стенд после всех тестов чистый и воспроизводимый.
   Дедлайн: 15 октября

### Тимофей

1. **Проверить транзакционные сессии на обоих вендорах**
   Описание: commit confirmed 180 на Cisco IOS-XE и configure session на Arista EOS — проверить, что таймеры реально работают: коммит не подтвержден → конфиг сам откатывается. Всякие тонкости синхронизировать с Лёшей, у него логика пайплайна.
   Дедлайн: 13 октября

2. **Собрать дашборды в Grafana под демо**
   Описание: состояние BGP, статус портов, доступность устройств — все на одном экране, который можно показывать экспертам. Подключить метрики, которые бэкенд отдает в Prometheus.
   Дедлайн: 14 октября

3. **Финальная стабильность стенда**
   Описание: проверить скрипт сброса на пошатанной после тестов лабе, убедиться, что стенд поднимается с нуля по одному манифесту и переживает демо-прогон от начала до конца.
   Дедлайн: 15 октября

### Лёша

1. **Связать шаги пайплайна деплоя в одну задачу Celery**
   Описание: pre-flight линт → dry-run → ручное подтверждение → транзакционное применение → post-check → коммит или откат. На каждом этапе обновлять статус и логи задачи. Если пост-чеки упали — коммит не отправляем, накатываем rollback.
   Дедлайн: 13 октября

2. **Завести регулярную проверку дрейфа через Celery Beat**
   Описание: каждые 15 минут фоновая задача снимает конфиги, сравнивает с эталоном из Git через hier_config, проставляет статусы IN_SYNC / DRIFT_DETECTED / UNREACHABLE. Плюс эндпоинты: POST /api/v1/drift/scan, GET /api/v1/drift/report, POST /api/v1/drift/remediate (накат компенсирующего патча через тот же пайплайн).
   Дедлайн: 14 октября

3. **Добавить роли доступа (RBAC)**
   Описание: три уровня — Viewer (только смотрит), Operator (запускает dry-run и применяет одобренные конфиги), Admin (полный доступ, управление пользователями). Минимальная реализация, но чтобы на демо можно было показать разграничение.
   Дедлайн: 15 октября

4. **Привести docker-compose к финальному виду**
   Описание: бэкенд + PostgreSQL + Redis + Celery-воркеры + Celery Beat + фронт + Prometheus + Grafana — всё поднимается одной командой с нуля. Согласовать с МП, он отвечает за общий файл.
   Дедлайн: 15 октября
